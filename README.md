# 商机助手 · 一句话查商机

面向销售运营的商机查询原型：输入自然语言需求，核对筛选条件，查看分页清单，下载完整Excel。全部业务数据均为模拟数据，不对应任何公司真实业务。

## 已实现范围

- 使用已验证的5,600条模拟商机，覆盖2024-01-01至2026-11-23创建的项目。
- 医疗、教育、政企、城市军团四个事业群；教育下含高教、基教、民办校，基教下设A至E市。
- 自然语言提取团队、年份、年份口径、阶段、业绩承诺、招投标要求与所需字段。
- 项目时间默认按创建日期筛选。用户明确指定预计成交日期或中标时间时，助手采用指定的日期口径。
- 在途为20%至80%，包含端点；100%为已赢单，90%不计入。
- 支持调整条件和18个字段；查询上级团队包含全部下级团队。
- 页面每页20条，Excel导出全量，字段及顺序与用户选择一致。
- 金额为数值，日期为Excel日期，空白保留为空，附一张查询说明表。

## 模型与查询边界

配置千问后使用真实Function Calling单Agent循环：模型自主选择读取口径、查询、校验、导出或澄清工具，后端执行后返回结果，模型再决定下一步。模型不生成任意SQL、不生成商机记录或金额；后端校验白名单字段及条件，使用参数绑定查询D1/SQLite。

未配置模型时明确显示“规则解析”，基础查询与导出仍可运行；不会把规则匹配声称为真实AI调用。真实模型调用失败时显示错误，不静默伪装成成功。

当前Agent循环在现有TypeScript后端实现，尚未集成Nanobot，也未使用RAG或多Agent架构。

## Agent设计

- 八种工具：`get_business_context`、`ask_user`、`query_opportunities`、`update_result_fields`、`summarize_current_result`、`list_current_subset`、`check_result`、`export_excel`。
- 保存最近统计的对象，支持“这些项目有几个在青岛 → 列出来”，将原47条民办校在途商机中的3条青岛项目实际展示与导出。单独列出会校验结果属于原清单，保留年份、团队、阶段及展示字段；无明确对象时先追问。兼容旧会话最后一条统计答复。
- 展示列调整独立处理：“商机阶段”和“项目阶段”统一为项目阶段列；新增列保留记录范围、年份口径和阶段筛选，页面定位并标出新增列，Excel同步更新。时间、日期、状态等含义不明确时先追问，选择后继续原任务。
- 统计追问使用当前完整结果，而非网页20行预览；可统计城市、团队、负责人、承诺、阶段及招投标情况，保留原清单和导出文件。A市等匿名团队名与项目所在市分开解释。
- 当前任务的对话记录完整保存，页面可上下滚动；模型仅接收最近12条对话和已确认的筛选上下文。
- 多轮增量筛选：未改变的年份、日期口径、项目阶段、承诺、金额范围和字段顺序会继承；页面可用“新任务”清空本次上下文。
- 会话及结果元数据保存在D1，按当前站点用户隔离；结果及会话在两小时后不可继续使用。该站点保持所有者私人访问，服务访问依赖Sites的私人访问边界。
- 每次查询生成结果编号与SHA-256数据指纹；导出必须通过记录数、唯一项目编号、金额合计及阶段范围检查。条件更新或数据变化后，旧结果不能继续下载。
- 工作簿可包含完整清单、按团队分表、招投标挂网日期缺失专项表和查询说明。分表、专项表是完整清单的子集，说明页提示不要重复加总。
- 专项表条件与主查询范围分开，避免“单列缺失挂网日期”误变成整份清单的招投标筛选。
- 模型最多8轮、工具最多12次，工具错误最多修正两次；无结果不会自动放宽条件。客户端显示实际工具状态，不展示模型内部推理。
- 首次请求需要澄清时暂停，回答后继续原任务；只发送统计和少量样例给模型，完整明细由后端处理。

### Agent验收任务

“查询2026年教育事业群在途商机，按团队分别整理，需要招投标但缺少预计挂网日期的项目单独列出，导出Excel。”

按预计成交年份、本模拟快照，应有205条主清单、7个团队分表、21条缺失挂网日期专项记录。工作簿共10个工作表，含完整清单和查询说明。继续说“只保留民办校团队、确保档，再加上项目编号”，应保留2026年、20%至80%阶段及原字段顺序。

## 环境变量

在ChatGPT Sites设置中保存以下后端环境变量，并标记为Secret。不要提交密钥到仓库。

| 名称 | 含义 |
|---|---|
| QWEN_API_KEY | 百炼API密钥 |
| QWEN_BASE_URL | 同地域OpenAI兼容地址，以/compatible-mode/v1结尾 |
| QWEN_MODEL | 模型名称，例如qwen-flash |

保存环境变量后需重新部署，运行时才使用新值。模型尚未配置时，页面清楚标注规则解析。

## 本地开发

项目使用Sites提供的Vinext/React starter，部署到Cloudflare Worker，数据库使用D1。结构迁移位于`drizzle/`，模拟数据种子位于`data/seed.json`，不在迁移文件中灌入数据。首次打开页面时按批次幂等初始化模拟数据。

安装依赖后：

```text
npm run db:generate
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_heavy_wong.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_calm_dazzler.sql
npm run dev -- --port 5186
```

本地模型配置保存在被Git忽略的`.dev.vars`中，字段参照`.env.example`。不应重新执行已经成功应用的迁移。

测试：

```text
node --test tests/workflow.test.ts tests/agent.test.ts
node node_modules/typescript/bin/tsc --noEmit
```

## 业务验收示例

“我需要一份2026民办校团队所有的在途商机（商机进度为20%-80%），包含负责人、所在团队、项目名称、客户名称、是否需要招投标、预计成交日期、预计挂网日期、项目金额，导出Excel。”

按预计成交年份筛选，本数据集应返回47条，网页分三页，Excel应含47条数据和8列。年份、快照、阶段端点等口径保存在Excel的“查询说明”页。

本轮追加600条合成商机，覆盖49个城市、30个省级地区、100条负责人记录，包含同名负责人、重复客户、多项目形态、跨年日期、金额边界与亏损/零利润等情况。原始5,000条数据保留，版本为sales-diversity-v2。

销售场景验收覆盖30个固定问题，标准答案由SQLite独立查询产生，见eval/sales-30-tasks.json。新增：条件取消、排序/前N条、客户名称检索、日期区间、预计利润状态及挂网日期缺失筛选；页面和Excel查询说明同步呈现实际条件。相对日期按数据快照解释。本轮是合成任务与真实模型的内部验收，不代表真实销售用户验证或通用模型准确率。
